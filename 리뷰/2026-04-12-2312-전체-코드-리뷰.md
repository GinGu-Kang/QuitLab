# 전체 코드 리뷰

- 작성 시각: 2026-04-12 23:12
- 범위: 매칭 알고리즘, 저장 계층, 관리자 인증, 결과/연락처/수신거부 플로우, 테스트 공백

## 주요 발견사항

### 1. [P1] 자격증 hard filter가 실제로는 추천에서 제외되지 않음

- 위치: `src/lib/matching.ts:116-126`, `src/lib/matching.ts:164-202`
- 문제: `hasRequiredLicense()`로 불일치를 판정하지만 `applyHardFilters()`에서는 `warningTags`만 추가하고 제외하지 않는다. 현재 제외 조건은 자본금 초과만 반영된다.
- 영향: 사용자가 `license: none`을 선택해도 `밀키트/HMR 제조`, `수제 맥주/브루어리`, `주스/스무디바` 같이 면허가 필요한 업종이 TOP 5에 그대로 노출된다.
- 판단: UI와 문서 모두 `hard filter`로 설명하고 있어서, 현재 동작은 제품 기대와 다르다.

### 2. [P1] Prisma 활성화 조건이 과도해서 운영 환경에서 조용히 로컬 파일 저장소로 폴백될 수 있음

- 위치: `src/lib/prisma.ts:8-18`
- 문제: Prisma 사용 조건이 `DATABASE_URL`과 `DIRECT_URL`을 모두 요구한다. 런타임에 `DATABASE_URL`만 제공되는 환경에서는 DB 연결 대신 `.local-data/storage.json` 폴백이 사용된다.
- 영향: 결과/연락처/분석 이벤트가 서버 로컬 파일에 저장되어 데이터 유실, 인스턴스 간 불일치, 쓰기 실패 가능성이 생긴다.
- 판단: 이 조건이라면 명시적으로 부팅 실패시키거나, 최소한 `DATABASE_URL`만으로 런타임 DB를 사용하게 바꾸는 편이 안전하다.

### 3. [P1] 관리자 세션 쿠키가 공개된 기본 시크릿으로 서명될 수 있음

- 위치: `src/lib/auth.ts:6-24`
- 문제: `ADMIN_SESSION_SECRET`이 없으면 `ENCRYPTION_KEY`, 그것도 없으면 `'quit-codex-admin-secret'`를 사용한다.
- 영향: 배포 설정이 비어 있으면 누구나 동일한 문자열로 관리자 세션 쿠키를 위조할 수 있다. `/admin`, `/api/admin/stats`, `/api/admin/export` 접근 통제가 사실상 무력화된다.
- 판단: 운영에서는 기본값 허용이 아니라 필수 환경변수로 강제해야 한다.

### 4. [P1] 개인정보 암호화 키도 고정 기본값으로 동작할 수 있음

- 위치: `src/lib/crypto.ts:5-10`
- 문제: `ENCRYPTION_KEY`가 없으면 `'quit-codex-local-dev-key'` 기반 SHA-256 결과를 암호화 키로 사용한다.
- 영향: 잘못 설정된 여러 환경이 동일한 키를 공유하게 되고, 전화번호 암호문과 해시의 보안 수준이 크게 떨어진다.
- 판단: 개발용 fallback은 로컬 개발에서만 허용하고, 운영에서는 반드시 키가 없으면 실패해야 한다.

### 5. [P2] 결과 페이지의 `다시 진단하기`가 스토어를 초기화하지 않음

- 위치: `src/components/result/ResultPageClient.tsx:101-103`, `src/store/diagnose-store.ts:56-138`
- 문제: 결과 페이지에서는 `/diagnose/step-1`로 이동만 하고 `reset()`을 호출하지 않는다. 반면 Zustand 스토어는 `persist`로 인덱스와 답변 상태를 저장한다.
- 영향: 사용자가 재진단을 시작해도 첫 질문이 아니라 이전에 풀던 위치나 완료 상태가 남아 있을 수 있다.
- 판단: 랜딩과 동일하게 재시작 경로에서 상태 초기화가 필요하다.

### 6. [P2] 연락처 저장 후 메일 전송 실패 시 API 전체가 실패로 응답함

- 위치: `src/app/api/contact/route.ts:24-49`
- 문제: 연락처 저장을 먼저 완료한 뒤 같은 `try` 안에서 `resend.emails.send()`를 기다린다.
- 영향: 메일 서비스가 일시 실패하면 사용자는 500을 보지만 개인정보/마케팅 동의는 이미 저장된 상태가 된다. 사용자가 재시도하면 중복 제출이나 상태 혼란이 생길 수 있다.
- 판단: 저장 성공과 메일 전송 성공을 분리해서 다뤄야 한다.

### 7. [P2] 결과 메일 HTML에 사용자 입력을 escaping 없이 삽입함

- 위치: `src/lib/email-template.ts:7-56`
- 문제: `nickname`과 `contact.name`이 HTML escape 없이 제목과 본문에 직접 삽입된다.
- 영향: 메일 클라이언트별로 레이아웃이 깨지거나 원치 않는 HTML 렌더링이 발생할 수 있다.
- 판단: 서버에서 문자열 escape 처리가 필요하다.

## 테스트 공백

- 현재 자동 테스트는 `src/lib/__tests__/matching.test.ts` 하나만 존재한다.
- 아래 항목은 회귀 테스트가 필요하다.
- `license` 불일치 업종 제외 여부
- `다시 진단하기` 클릭 시 스토어 초기화 여부
- `contact` 저장 성공 후 이메일 실패 시 응답 정책
- 관리자 시크릿/암호화 키 미설정 시 부팅 또는 요청 실패 정책

## 결론

- 현재 서비스는 기본 플로우 자체는 동작하지만, 운영 관점에서는 보안 설정과 데이터 저장 정책에 P1 이슈가 있다.
- 특히 자격증 필터, Prisma 폴백, 관리자 세션 시크릿 fallback은 우선순위를 높게 두고 바로 수정하는 편이 맞다.
