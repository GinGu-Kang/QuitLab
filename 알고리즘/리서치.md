# 매칭 알고리즘 리서치

## 개요

이 문서는 현재 서비스에 구현된 매칭 엔진을 분석한 결과를 정리한다.
분석 기준 코드는 다음 파일이다.

- `src/lib/matching.ts`
- `src/types/index.ts`
- `src/data/startup-items.json`
- `src/data/personality-questions.json`
- `src/data/career-synergy.json`
- `plans/PHASE-2-matching-algorithm.md`

핵심 결론부터 말하면, 현재 알고리즘은 다음 네 층으로 동작한다.

1. 하드 필터로 명백히 불가능한 업종을 제거한다.
2. 역량 적합도, 성향 적합도, 경력 시너지, 시장 매력도를 계산한다.
3. 현실 조건 기반 페널티를 차감한다.
4. 최종 점수 상위 5개를 결과로 반환한다.

추가로 결과 설명 문자열, 리스크 경고, 역량 갭, 준비 가이드도 같은 단계에서 함께 생성한다.

---

## 입력과 출력

### 입력 구조

입력 타입은 `DiagnoseInput`이며 세 블록으로 구성된다.

```ts
hardFilter: {
  capital: number
  region: 'metro' | 'city' | 'town' | 'rural'
  license: string
  timing: 'now' | '3m' | '6m' | '1y'
  family: 'single' | 'dual' | 'sole'
  income: number
  career: CareerKey
  loan: boolean
}
competencyScores: number[12]
personalityAnswers: ('a' | 'b')[10]
```

### 출력 구조

출력 타입은 `MatchResult[]`이고, 최종적으로 상위 5개만 반환한다.

각 결과에는 다음 정보가 들어간다.

- 업종 원본 데이터
- `finalScore`
- 세부 점수 분해값
- `riskWarnings`
- `competencyGap`
- `warningTags`
- 설명 문장 3종
  - `reason`
  - `marketSummary`
  - `preparationGuide`

## 현재 알고리즘 흐름

### 1. 데이터 로드

정적 JSON을 메모리에 올린 뒤 계산한다.

- `startup-items.json`: 129개 업종
- `personality-questions.json`: 10개 성향 문항
- `career-synergy.json`: 14개 경력 × 카테고리 매트릭스

이 구조는 서버리스 환경에서 빠르고 결정론적이다.

### 2. 하드 필터

`applyHardFilters()`가 먼저 실행된다.

#### 2-1. 자본금 필터

```ts
effectiveCapital = capital + (loan ? 10000 : 0)
excluded = item.investmentMin > effectiveCapital
```

- `loan=true`이면 1억을 추가 투입 가능 자본으로 본다.
- 투자 하한이 유효 자본보다 크면 바로 제외된다.

#### 2-2. 자격증 필터

필수 자격증이 있어도 기본적으로 제외하지 않는다.
대신 `warningTags`에 경고만 붙인다.

현재 구현은 사용자가 선택한 면허를 다음 3종으로 대략 매칭한다.

- `food`: 식품, 조리, 제과, 영업신고
- `beauty`: 미용, 뷰티, 이용
- `pro`: 공인중개사, 세무사, 노무, 법무, 행정사, 전문

주의점:
`KC인증 등`, `업종별 상이`, 기타 특수 인허가를 세밀하게 판정하지는 않는다.

#### 2-3. 지역 페널티

현재 지역 필터는 제거가 아니라 감점이다.

```ts
metro + 농업/1차산업 => -15
rural + IT/테크 | 문화/엔터 | 부동산 => -12
town + 문화/엔터 => -8
```

의미:
엑셀 계획서의 "후순위" 개념을 단순 규칙 기반 감점으로 번역한 상태다.

#### 2-4. 퇴사 시기 페널티

```ts
timing === 'now' && (entryBarrier >= 4 || 자격증 미보유) => -10
```

즉시 퇴사를 선택한 사용자가 준비기간이 긴 업종으로 가는 것을 눌러준다.

#### 2-5. 가족 상황 페널티

```ts
family === 'sole' && (
  workLifeBalance <= 2 ||
  closureRate >= 35 ||
  risk competency >= 4
) => -8

family === 'dual' && workLifeBalance >= 4 => +3 효과
```

구현상 `dual`은 `-3` 페널티를 더해서 결과적으로 보너스처럼 작동한다.

#### 2-6. 희망 수입 페널티

`avgMonthlyRevenue`와 `operatingMargin` 문자열을 파싱해 예상 월 순이익 구간을 계산한다.

```ts
if profit.max < income => -12
if profit.min < income <= profit.max => -6
```

장점:
단순 매출이 아니라 이익률을 곱해 현실 수익 기준으로 보려는 시도가 들어가 있다.

한계:
문자열 포맷이 다양한 업종은 파싱 실패 시 페널티가 빠진다.

## 소프트 매칭

### 3. 역량 적합도

`calcCompetencyFit()`는 현재 알고리즘의 가장 중요한 축이다.

공식:

```ts
gap = abs(userScore - requiredScore)
contribution = (5 - gap) * requiredScore
competencyFit = sum(contribution) / sum(5 * requiredScore) * 100
```

해석:

- 요구 점수가 높은 역량일수록 가중치가 커진다.
- 사용자가 모든 축에서 딱 맞으면 100점이다.
- 요구 점수가 낮은 역량에서 조금 어긋나는 것은 영향이 작다.

이 점수는 최종 점수에 50% 비중으로 반영된다.

### 4. 성향 적합도

`calcPersonalityFit()`는 10문항의 A/B 선택에서 나온 선호 태그와 업종 태그를 비교한다.

현재 구현은 카테고리 문자열 직접 일치보다 조금 더 넓은 규칙을 쓴다.

#### 4-1. 아이템 태그 생성

`buildItemTags()`가 다음 정보로 태그를 만든다.

- 카테고리 alias
- 운영형태
- 필요 인력
- 주말 근무
- 워라밸
- 성장 잠재력
- 진입장벽
- 대인관계/영업 요구
- 기술 요구
- 체력 요구

예:

- `온라인형`이면 `온라인`, `온라인 비즈니스`, `집/사무실에서 컴퓨터 앞에서`
- `무인형`이면 `무인`, `무인/자동화`, `1인서비스`
- `tech >= 4`이면 `기술이 핵심 경쟁력이어야`, `SaaS`, `AI`, `IoT`

#### 4-2. 점수 계산

```ts
10문항 중 몇 문항이 item tag와 매칭되는지 / 10 * 100
```

즉, 문항별 가중치는 모두 동일하다.

이 점수는 최종 점수에 30% 반영된다.

### 5. 경력 시너지

`calcCareerSynergy()`는 `career-synergy.json`을 직접 조회한다.

```ts
score = matrix[career][category] // 0~4
careerFit = score * 25           // 0~100
```

중요:
원래 계획 문서에는 `0~20 보너스` 성격으로 적혀 있었지만,
현재 구현은 0~100 스케일로 올린 뒤 최종 점수에서 10%를 곱한다.

즉 최종 기여량은 사실상 0~10점 범위다.

### 6. 시장 매력도

```ts
raw = growthPotential - competitionLevel + differentiationRoom
marketAttractiveness = ((raw + 3) / 12) * 100
```

입력 범위상 `raw`는 `-3 ~ 9`로 가정된다.
이 점수는 최종 점수에 10% 반영된다.

---

## 최종 점수 공식

현재 공식은 다음과 같다.

```ts
finalScore =
  competencyFit * 0.5 +
  personalityFit * 0.3 +
  careerFit * 0.1 +
  marketAttractiveness * 0.1 -
  penalty
```

이후 `0~100`으로 clamp 한다.

해석:

- 주 점수는 4개 축의 가중합
- 현실 조건은 보너스가 아니라 감점 계층으로 처리
- 필터에서 제외되지 않은 업종들끼리는 감점량이 최종 순위를 크게 흔든다

## 부가 결과 생성

### 7. 리스크 경고

`generateRiskWarnings()`는 다음 조건을 경고로 붙인다.

- 폐업률 25% 이상
- 경쟁강도 4 이상
- 계절성 `높음`
- 성장 잠재력 2 이하

### 8. 역량 갭

`calcCompetencyGap()`는 다음 조건만 남긴다.

- 업종 요구 점수 3 이상
- 사용자 점수가 요구보다 낮음

이 결과는 분석근거 탭과 가이드 탭에서 사용된다.

### 9. 설명 텍스트

문장 생성은 규칙 기반이다.

- `buildReason()`: 강점 역량 2개 또는 운영 적응력 중심 설명
- `buildMarketSummary()`: 투자비, 월매출, 이익률, 손익분기 요약
- `buildPreparationGuide()`: 가장 큰 역량 갭과 준비 포인트 설명

장점:
LLM 없이도 일관된 결과를 만든다.

한계:
업종마다 문장 구조가 비슷해질 수 있다.

## 계획 문서 대비 차이

현재 구현은 기본 방향은 유지하지만, 몇 가지는 계획 문서와 다르다.

### 1. 경력 시너지 스케일

계획:

- 0~4를 `*5`해서 0~20

현재:

- 0~4를 `*25`해서 0~100
- 이후 최종 점수에 `0.1` 곱함

실질 영향:

- 결과 기여량은 0~10점
- 계획상 "작은 보너스"보다는 다소 큰 축으로 동작한다

### 2. 성향 점수 계산 방식

계획:

- 태그 집계 후 비율 기반 매칭

현재:

- 문항별 yes/no 매칭 수 기반
- 각 문항 동등 가중
- 업종 측 태그는 alias와 규칙 태그로 확장

실질 영향:

- 성향 적합도가 더 직관적이고 안정적
- 대신 세밀한 태그 빈도 차이는 반영되지 않음

### 3. 현실 조건 필터

계획:

- 하드필터 일부는 제거, 일부는 경고/후순위

현재:

- 제거: 자본금
- 경고: 자격증
- 감점: 지역, 즉시 퇴사, 가족 상황, 수입 미달

실질 영향:

- 제거보다 감점 중심이라 결과 풀이 넓게 유지됨
- 다양성에는 유리하지만, 아주 엄격한 현실 제약엔 덜 보수적임

## 강점

### 1. 결정론적이다

같은 입력이면 같은 결과가 나온다.

### 2. 데이터 의존 구조가 단순하다

엑셀 -> JSON -> 순수 함수 구조라서 디버깅이 쉽다.

### 3. 설명 가능성이 높다

점수 분해, 경고, 갭 분석이 모두 규칙 기반이라 사용자가 납득하기 쉽다.

### 4. 결과 다양성이 충분하다

플레이그라이트 기반 검증 스크립트 `scripts/verify-diversity-playwright.cjs`로
고정 시나리오 40개를 돌렸고, 서로 다른 1위 결과가 15개 나왔다.

요구 조건:

- 최소 8개 이상

검증 결과:

- 15개

## 약점과 리스크

### 1. 자격증 판정이 거칠다

정규식 3갈래만 있고, 업종별 인허가의 세부 난도를 반영하지 않는다.

### 2. 지역 필터가 매우 제한적이다

현재는 카테고리 몇 개만 감점한다.
실제 상권, 인구밀도, 지방 적합성은 거의 반영되지 않는다.

### 3. 수익성 파싱 실패 시 페널티가 빠진다

`업종별 상이`, `변동폭큼` 같은 문자열은 계산에서 제외된다.

### 4. 성향 적합도는 문항 간 중요도 차이가 없다

주말 근무 허용 여부와 성장 목표 같은 문항이 동일 비중으로 들어간다.

### 5. 카테고리 alias는 수동 규칙이다

지금 구조는 유지보수성이 낮고, 카테고리 확장 시 누락 위험이 있다.

## 추천 개선 방향

### 1. 경력 시너지 스케일을 문서 기준으로 재정렬할지 결정

현재 구현은 충분히 잘 동작하지만, 계획 문서와 숫자 의미가 다르다.
둘 중 하나로 정리하는 것이 좋다.

- 문서에 맞춰 0~20 보너스로 축소
- 또는 현재 구현을 기준으로 문서를 수정

### 2. 하드필터를 설정 가능한 규칙 테이블로 분리

지금은 `matching.ts` 안에 규칙이 박혀 있다.
추후에는 JSON 또는 별도 설정 파일로 빼는 편이 낫다.

### 3. 성향 적합도에 문항 가중치 도입

예:

- 주말 근무
- 운영형태
- 고객 접점

같은 실제 행동 차이를 더 크게 반영할 수 있다.

### 4. 수익성 추정 로직 개선

업종별 상이, 변동폭큼 같은 문자열을 별도 분류해
"불확실성 페널티"로 처리하는 편이 낫다.

### 5. 설명 문장을 템플릿 세분화

현재 텍스트는 안정적이지만 업종별 개성이 부족하다.
카테고리별 템플릿을 두면 읽는 맛이 좋아진다.

## 요약

현재 매칭 알고리즘은 다음 성격을 가진다.

- 핵심 역량 중심
- 성향/경력/시장성을 보조 축으로 반영
- 현실 조건은 제거 + 감점 계층으로 처리
- 결과 설명까지 한 번에 생성
- 실제 다양성 검증 기준 최소 요구를 충분히 넘김

즉, 현재 버전은 MVP를 넘어서 "설명 가능한 추천 엔진" 수준까지는 올라와 있다.
다음 단계는 정확도 개선보다도 규칙 외부화, 문서-구현 정합성, 세부 인허가/수익성 모델 보강이다.
